# CodePilot-Go 初版架构草稿

## 目标与范围

通过 Go + Gin + Eino 构建 Bug 定位与修复后端服务。

输入：授权的本地 Go 示例仓库及 Bug 描述。
输出：执行记录、Diff、测试结果、最终状态及说明。

只操作原仓库的独立副本，首版采用单 Agent。

## 任务管理

- 提交成功后返回 task_id，客户端通过轮询查询结果。
- 提交请求结束或客户端断连，不取消后台任务。
- 同时执行 1 个修复任务，其余进入有界内存队列。
- 队列满时拒绝新提交。
- 状态存于内存，服务进程退出后不支持恢复。
- 从接收成功时开始计算总超时，排队和执行共享预算。
- Task Manager 管理状态、取消、超时、预算和最终判定。
- Agent 通过受控工具开展修复，报告执行结果。

状态为 pending、running、succeeded、failed、cancelled、timed_out。
后四种为终态，进入后不再改写；晚到结果可附加记录。

## 首个 Bug 案例

判断整数是否属于闭区间 [min, max]。
首个案例只考虑 min <= max 的合法输入。

示例区间 [1,5]：
- 输入 1、3、5，预期为 true。
- 输入 0、6，预期为 false。

目标错误：错误地排除了右端点 5。

## 执行与验收边界

- Agent 首次执行目标仓库代码前，必须具备路径校验、
  最小 Docker 沙箱、执行超时和迭代／重试上限。
- 工具限制可操作路径、权限和输出大小，不读取凭据。
- 先在原始版本复现问题，再验证修复。
- 固定验收测试由评测端保存，Agent 不可修改。
- 成功由外层程序结合固定验收、原有测试、修改范围
  和任务预算判定，不采用模型的成功自述。
